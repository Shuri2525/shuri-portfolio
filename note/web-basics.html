01
# しくみ

Webページが表示されるまで

URLを入れると、住所を調べ（DNS）、サーバーにファイルをお願いし（HTTP）、届いたHTML・CSS・画像をブラウザが組み立てて表示します。印刷でいう「入稿から刷り上がりまで」が、見られるたびに毎回起きているイメージです。

URLは「どこの・何を」の住所

URLは、通信の方法（https://）、サイトの名前（ドメイン）、ファイルの場所（パス）に分かれています。? 以降のクエリはページに追加の情報を渡し、# 以降のハッシュはページ内の位置を指します。

DNSは住所録

コンピューター同士は、185.199.108.153 のような数字の住所（IPアドレス）でやりとりします。人が覚えやすいドメインを、この数字に変換するしくみがDNSです。「独自ドメインを設定する」とは、この住所録に登録することです。

HTTPのやりとりとステータスコード

ブラウザが「このファイルをください」とリクエストし、サーバーが中身と一緒に結果の番号（ステータスコード）を返します。200は成功、301は引っ越し済み、404はページが見つからない、500はサーバー側のエラーです。

HTTPSは通信を暗号化した形で、今はこちらが前提です。

紙では紙は刷ったものを1回届けて終わりですが、Webは見る人がページを開くたびに、このやりとりが毎回起きています。

ブラウザが画面を描くまで

ブラウザはHTMLから文書の構造（DOM）を、CSSから見た目のルール（CSSOM）を作り、2つを合わせて位置を計算（レイアウト）し、色を塗って（ペイント）表示します。

CSSや一部のJavaScriptは読み終わるまで表示を止めるので、重いファイルが多いほど白い画面の時間が長くなります。

02
# 見た目

Webの色はRGBで考える

画面は光の三原色RGBで色を作ります。印刷のCMYKとは仕組みが逆なので、同じ数値の置き換えでは同じ色になりません。見る画面によっても少しずつ色が変わります。

RGBは光の強さを0〜255で表す

赤・緑・青それぞれの光の強さを、0〜255の256段階で指定します。3色すべて255で白、すべて0で黒です。

紙では紙のインキは重ねるほど暗くなりますが、画面の光は重ねるほど明るくなります。CMYKとは考え方が逆です。

同じ色をいろいろな書き方で

#3F3B3A は、RGBを2桁ずつ16進数で書いたものです。hsl() は色相・彩度・明度で指定するので、「同じ色味で少し明るく」が作りやすい書き方です。

oklch() は人の目が感じる明るさに近い数値で指定でき、明るさをそろえた配色が組みやすいのが特長です。主要ブラウザで使えます。

色の範囲（色空間）も画面ごとに違う

Webの標準の色空間はsRGBです。最近のiPhoneやMacはもっと広いDisplay P3を表示でき、CSSの color(display-p3 …) で指定できます。対応していない画面では、sRGBの範囲に丸めて表示されます。

印刷の色をWebで使うとき

ロゴやブランドカラーをWebで使うときは、CMYKの値を機械的に変換するのではなく、画面で見比べて合わせたRGBの値をWeb用の色として別に決めておくのが確実です。

半透明は rgb(63 59 58 / 50%) のように、最後に不透明度を足して書けます。

紙ではDICなどの特色も同じで、Web用には近い見た目のRGBを決めて、色見本と一緒に管理します。

03
# 見た目

Webの画像は「形式・px・重さ」

Webの画像は、どの形式で、何pxで、何KBで用意するかで、きれいさと表示の速さが決まります。dpiではなく、表示サイズの何倍のpxかで考えます。

ラスターとベクター

写真のように点の集まりでできた画像がラスター、ロゴやアイコンのように線と面の式でできた画像がベクターです。WebのベクターはSVG形式で、どれだけ拡大してもぼけず、ファイルも軽く済みます。

紙ではIllustratorのデータをWebで使うなら、SVGで書き出すとそのまま近い形で使えます。

形式の選び方

写真はJPG、透過や図はPNGが基本でした。今は、どちらも軽くできるWebPや、さらに軽いAVIFが主要ブラウザで広く使えます。

<picture> を使うと、新しい形式に対応していないブラウザにはJPGを出す、といった出し分けができます。

1pxは1点とは限らない

最近の画面は、1pxを2×2や3×3の細かい点で表示します（デバイスピクセル比）。表示幅400pxの場所に置く画像は、800pxで用意するとくっきり見えます。

Webでは画像のdpiの数値は表示に関係なく、px数だけで大きさが決まります。

紙では印刷は「原寸で350dpi」、Webは「表示サイズの2倍のpx」と覚えると整理しやすくなります。

画面に合う画像を選ばせる

srcset と sizes を書くと、ブラウザが画面幅に合った画像を選んで読み込みます。スマホに大きすぎる画像を送らずに済みます。

loading="lazy" で見える位置に来るまで読み込みを待たせ、width・height で場所を先に確保すると、読み込み時に文字がずれません。

04
# しくみ

HTMLは文書の骨組み

HTMLは「ここは見出し」「ここはナビ」と、文章の意味と構造を伝えるためのものです。見た目はCSSに任せ、HTMLでは中身の役割を正しく書きます。

タグは意味のラベル

HTMLは、内容をタグで囲んで「これはリンク」「これは見出し」と意味を付けます。href のような属性で、リンク先などの追加の情報を書きます。

ページの骨組みを意味のある要素で

<div> だけでも見た目は作れますが、header・nav・main・article・footer などの意味のある要素（セマンティック要素）を使うと、検索エンジンや読み上げソフトがページの構造を正しく理解できます。

紙では原稿に「大見出し」「本文」「キャプション」と指定を入れるのと同じで、役割を書いておくことで、あとから誰が見ても構造がわかります。

見出しは階層どおりに

h1 はページの名前で、基本は1つ。その下に h2（章）、h3（節）と順に並べます。文字を大きくしたいだけで見出しタグを使ったり、h2 の次に h4 へ飛ばしたりはしません。大きさはCSSで変えます。

画面に出ない head も大事

<head> には、文字コード、スマホ用の表示設定（viewport）、タブや検索結果に出るタイトルと説明文、CSSの読み込みなどを書きます。viewportがないと、スマホでPC用の画面が縮小されて表示されます。

05
# しくみ

CSSのしくみ

CSSは見た目の指示書です。「どの要素に」「どんな見た目を」当てるかを書きます。ルールがぶつかったときの優先順位（カスケード）を知ると、思いどおりに効かない理由がわかります。

書き方の基本

「どれに（セレクタ）」「何を（プロパティ）」「どうする（値）」の組み合わせで書きます。クラス名（.card）に指定して、同じ見た目をいろいろな場所で使い回すのが基本です。

ぶつかったときの勝ち負け

同じ要素に複数の指定が当たったときは、セレクタの強さ（詳細度）が高いほうが勝ちます。強さはおおむね ID ＞ クラス ＞ タグ。強さが同じなら、後に書いたほうが勝ちます。

color や font などは親から子へ継承されます。!important は最後の手段です。

すべての要素は箱

要素は、中身（content）のまわりに内側の余白（padding）、枠線（border）、外側の余白（margin）を持つ箱として扱われます。

box-sizing: border-box を指定すると、幅に padding と border を含めて計算でき、サイズが読みやすくなります。今はほぼ定番の設定です。

紙では版面とマージンの考え方とよく似ています。違うのは、箱の中にさらに箱が入れ子になっていくところです。

並べ方はFlexboxとGrid

横一列や縦一列に並べるならFlexbox、縦横の格子に並べるならGridが向いています。どちらも gap で間隔をそろえられます。

紙ではグリッドシステムを使ったレイアウトを、そのままコードで再現できるのがGridです。

# 体験・品質

レスポンシブと単位

Webには決まった紙のサイズがありません。スマホからPCまで、画面の幅に合わせて伸び縮みする前提で、単位と切り替えのルールを決めておきます。

画面幅で切り替える

まず <meta name="viewport" content="width=device-width, initial-scale=1"> で、スマホの画面幅をそのまま使うよう指定します。そのうえで @media (max-width: 1024px) { … } のように、決めた幅（ブレークポイント）でレイアウトを切り替えます。

紙では紙は仕上がりサイズが1つに決まっていますが、Webは何通りもの画面幅で崩れないかを考えます。

単位の使い分け

文字は rem、余白は rem か px、幅は % やGridの fr を使うのがよくある組み合わせです。rem で書いておくと、見る人がブラウザの文字サイズを大きくしたときにも一緒に大きくなります。

スマホで画面いっぱいの高さを作るときは、アドレスバーの出入りを考えた dvh が使えます。

clamp()でなめらかに

font-size: clamp(28px, 4vw, 48px) と書くと、「画面幅の4%で変わるけれど、28pxより小さく・48pxより大きくはしない」という指定になります。ブレークポイントで段階的に変えるより、なめらかに大きさが変わります。

置かれた場所の幅で変える

コンテナクエリを使うと、画面全体ではなく、部品が置かれた箱の幅に合わせて形を変えられます。同じカードを、細いサイドバーでは縦並び、広い本文では横並びにする、といった作り方ができます。主要ブラウザで広く使えるようになっています。

07
# 見た目

Webのタイポグラフィ

Webの文字は、見る人の端末にあるフォントか、読み込んだWebフォントで表示されます。きれいさと読み込みの軽さのバランスを取るのがポイントです。

フォントは端末で決まる

font-family には候補を順番に書きます。ブラウザは先頭から探して、使えるものがなければ次へ進み、最後は sans-serif のような総称の書体で表示します。

紙では紙は指定したフォントで必ず刷られますが、Webは見る人の環境で変わります。どのフォントで表示されても崩れない組み方を意識します。

日本語のWebフォントは重い

欧文フォントは数十KB程度ですが、日本語は文字数が多く、1書体で数MBになることもあります。Google Fontsなどは、使う文字の分だけ分割して読み込む（サブセット）ことで軽くしています。形式は圧縮率の高いWOFF2が基本です。

font-display: swap を指定すると、読み込みが終わるまで代わりのフォントで先に文字を表示できます。

Webで読みやすい本文

本文の文字サイズ16px以上
行の高さ（line-height）1.7〜1.9
1行の文字数（日本語）35〜45字
字間（letter-spacing）0.04〜0.08em

スマホでは画面に近づけて読まないので、紙より大きめが基本です。

紙では紙の本文は11〜14Q（約8〜10pt）。Webの16pxは、ひと回り大きい感覚です。

詰めと可変フォント

font-feature-settings: "palt" を指定すると、かっこや句読点の余白が詰まり、見出しが締まって見えます。長い本文はベタ組みのほうが読みやすいので、見出し中心に使います。

可変フォントは、1つのファイルで太さを細かく変えられるフォントで、何書体も読み込むより軽く済みます。

# しくみ

JavaScriptでできること

JavaScriptは、ページに「動き」と「判断」を加えるプログラムです。HTMLが骨組み、CSSが見た目なら、JavaScriptはふるまいの担当です。

DOMとイベント

JavaScriptは、ブラウザが作った文書の構造（DOM）を読み書きできます。「ボタンが押されたら（click）」「メニューにクラスを付けて開く」のように、イベントをきっかけにページを変えるのが基本の使い方です。

このポートフォリオのカテゴリの切り替えや作品の詳細表示も、この仕組みで動いています。

読み込み方で表示の速さが変わる

普通に読み込むと、JavaScriptの実行が終わるまでHTMLの読み込みが止まります。defer を付けると、HTMLを最後まで読んでから順番に実行されるので、表示を邪魔しません。

順番を問わないアクセス解析のタグなどは、読み込めたらすぐ実行する async が向いています。

CSSでできることはCSSで

ホバーの変化、なめらかな切り替え、アコーディオンの開閉（<details>）など、以前はJavaScriptが必要だった表現の多くが、HTMLとCSSだけでできるようになりました。中身に応じてスタイルを変える :has() も主要ブラウザで広く使えます。

JavaScriptは少ないほど、軽くて壊れにくいページになります。

ライブラリとフレームワーク

大きなサイトやアプリでは、画面を部品（コンポーネント）に分けて作る React・Vue・Svelte などのフレームワークがよく使われます。さらにその上に、ページの生成や表示の速さまで面倒を見る Next.js や Astro などがあります。

ポートフォリオのような小さなサイトなら、素のJavaScriptで十分です。

# 体験・品質

表示速度とCore Web Vitals

表示が遅いページは、読まれる前に閉じられてしまいます。Googleは「読み込み・反応・ずれ」の3つの指標（Core Web Vitals）で、ページの使い心地を測っています。

3つの指標と目標値

LCP（一番大きい要素が出るまで）2.5秒以内
INP（操作してから反応するまで）200ms以内
CLS（レイアウトのずれ）0.1以下

実際に訪れた人のデータで、訪問の75%がこの値を満たしていれば「良好」です。PageSpeed Insightsで調べられます。

LCPを速くする

LCPの対象は、たいてい一番上の大きな写真や見出しです。その画像をAVIFやWebPで軽くし、表示サイズに合ったpx数にします。fetchpriority="high" で優先して読み込ませる、使うWebフォントの数を絞る、なども効果があります。

CLSを防ぐ

読んでいる途中で文字が急に下にずれる原因の多くは、あとから読み込まれる画像や広告です。画像に width・height（または aspect-ratio）を指定して場所を先に確保すると、ずれを防げます。

キャッシュで2回目を速く

ブラウザは一度読み込んだCSSや画像を保存（キャッシュ）して、次からはそれを使います。そのぶん速くなりますが、ファイルを更新しても古いものが表示されることがあります。

そのときは、style.css?v=20261115 のように名前やクエリを変えると、新しいファイルとして読み込まれます。このポートフォリオでも使っている方法です。

10
# 体験・品質

アクセシビリティ

目が見えにくい人、キーボードだけで操作する人、明るい屋外でスマホを見ている人。いろいろな状況でも使えるようにすることがアクセシビリティで、国際的な基準がWCAG（最新は2.2）です。

文字と背景のコントラスト比

文字と背景の明るさの差をコントラスト比で表します。WCAGの基準（AA）では、本文は4.5:1以上、大きな文字は3:1以上が必要です。おしゃれに見える薄いグレーの小さな文字は、基準を下回りやすいので注意します。

紙では印刷では読める淡い色も、画面の明るさや屋外の光で見えにくくなることがあります。

押せる大きさ

WCAG 2.2では、ボタンやリンクなど押せる部分を24×24px以上にする（または周りに十分な間隔をとる）ことが基準（AA）になりました。さらに押しやすくするなら、44×44pxが目安です。

キーボードだけでも使える

マウスを使わず、Tabキーで順番に移動して操作する人もいます。すべてのリンクやボタンにTabでたどり着けるか、いまどこを選んでいるかの枠（フォーカス表示）が見えるかを確認します。見た目のためにフォーカスの枠を消すのは避けましょう。

代替テキストと色以外の手がかり

画像には、内容を言葉で伝える alt を書きます。読み上げソフトはこれを読みます。飾りだけの画像は alt="" にします。

エラーを赤い枠だけで示すと、色の見分けがつきにくい人には伝わりません。アイコンや文章も添えて伝えます。

# 公開・運用

SEOとOGP

検索結果やSNSでシェアされたときに「どう見えるか」も、ページのデザインの一部です。中身を正しく伝えるタグを書いておくのが基本です。

検索結果に出る部分

検索結果の青い見出しは主に <title>、その下の説明文は meta description から作られます。どちらもページごとに中身に合わせて書きます。ただし、検索エンジンが内容に合わせて書き換えて表示することもあります。

URLを1つにまとめる

同じ内容のページが、クエリや # 付きなど複数のURLで見られる場合は、<link rel="canonical"> で「正式なURLはこれ」と伝えます。評価が分散するのを防げます。

PC版とスマホ版が別のページになっている場合は、rel="alternate" で対応関係を示します。

構造化データ

「これは人物」「これは記事で、書いた人はこの人」といった情報を、検索エンジン向けに決まった形式（JSON-LD）で書いておくのが構造化データです。検索結果に詳しい情報が表示されるきっかけになります。

SNSで見えるカード（OGP）

SNSでURLをシェアしたときのカードは、og:title・og:description・og:image・og:url で決まります。画像は1200×630px（1.91:1）が定番です。端が切れても大丈夫なよう、大事な文字は中央に寄せます。

SNS側でも情報が保存されるので、変更がすぐ反映されないことがあります。

12
# 公開・運用

公開と運用

Webは公開してからが本番です。ドメイン・サーバー・HTTPSをそろえて公開し、Gitで変更の記録を残しながら、見られ方を確かめて直し続けます。

公開に必要な3つ

サイトの名前（ドメイン）、ファイルの置き場所（サーバー）、通信を暗号化するHTTPSの証明書の3つが必要です。GitHub Pagesのような無料のサービスなら、この3つがまとめて用意されます。このポートフォリオもGitHub Pagesで公開しています。

Gitで変更を記録する

Gitは、ファイルの変更を記録しておく仕組みです。変更をまとめて記録（commit）し、GitHubに送る（push）と公開されます。記録が残っているので、いつでも前の状態に戻せます。本番とは別の作業場所（ブランチ）で試すこともできます。

公開前のチェック

公開ボタンを押す前に、スマホとPCの両方で表示が崩れていないか、リンク切れはないか、画像に alt があるか、検索結果やSNSでの見え方、表示速度、フォームの送信まで確認します。

紙では入稿前の最終チェック（トンボ・塗り足し・フォント）と同じ役割です。

公開してからが本番

Google Analyticsで「どのページがどれくらい見られているか」、Search Consoleで「どんな言葉で検索されたか」がわかります。データを見て気づいたことを直し、また公開する、をくり返してサイトを育てていきます。

紙では紙は刷ったら直せませんが、Webはいつでも直せます。その分、直し続ける前提で作ります。

GLOSSARY

用語集

alt
画像の内容を言葉で伝える属性。読み上げや画像が出ないときに使われる。第10回
CDN
世界中のサーバーにファイルを置き、近い場所から届ける仕組み。第9回
Core Web Vitals
Googleがページの使い心地を測る3つの指標（LCP・INP・CLS）。第9回
CSS
ページの見た目を指定する言語。第5回
DNS
ドメインをIPアドレスに変換する仕組み。第1回
DOM
ブラウザがHTMLから作る、文書の構造。JavaScriptで操作できる。第8回
Git
ファイルの変更履歴を記録する仕組み。第12回
HTML
ページの中身と構造を書く言語。第4回
HTTP / HTTPS
ブラウザとサーバーのやりとりの決まり。Sは暗号化された形。第1回
OGP
SNSでシェアされたときのタイトル・説明・画像を指定する仕組み。第11回
rem
ページの基準の文字サイズ（通常16px）の何倍かを表す単位。第6回
sRGB
Webの標準の色空間。第2回
SVG
線と面の式でできた画像形式。拡大してもぼけない。第3回
WCAG
Webアクセシビリティの国際的な基準。最新は2.2。第10回
WOFF2
Webフォントの圧縮形式。第7回
キャッシュ
一度読み込んだファイルをブラウザが保存しておく仕組み。第9回
コンテナクエリ
部品が置かれた箱の幅で、スタイルを切り替える仕組み。第6回
詳細度
CSSの指定がぶつかったときの優先度。第5回
セマンティクス
HTMLの要素が持つ意味。第4回
デバイスピクセル比
画面の1pxを、何点の細かさで表示するかの比率。第3回
ブレークポイント
レイアウトを切り替える画面幅。第6回
ボックスモデル
すべての要素を中身・内側の余白・枠線・外側の余白の箱として扱う考え方。第5回
レスポンシブ
画面幅に合わせてレイアウトが変わるつくり。第6回
